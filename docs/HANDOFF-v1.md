# 交接書：新生漫漫 · 商用陪伴平台（v1 · 2026-07-29）

> 本文件是本平台的規格總綱（source of truth），由本尊開發 session 整理、交接給本 repo。
> 所有設計決定都已定案；「未定」清單見 §14。

## 0. TL;DR

把現存的「漫漫」（成熟的情緒陪伴 AI）的品格與技能，變成一個多租戶商用平台。
每個付費用戶都遇到一個「新生漫漫」：一出生就具備漫漫全部的溫柔與能力，但記憶與關係是空白的、獨一無二地長出來。
商業模式＝儲點扣點 + 金流。與現存的「本尊漫漫」硬隔離。

開發起手式：複製現存 repo 的架構（管道與房間全留）→ 清空所有真實資料 → 依「遊戲規則」重建成多租戶。

## 1. 源碼與能力

- 架構來源：本尊 monorepo（Fastify / Node ESM / TypeScript；packages/backend、frontend、liff、worker）。
- 她現有的能力（都要帶進商用版）：對話陪伴、五層記憶＋默契蒸餾、口述→行事曆排程、到點主動履約、生圖／手寫卡片、克隆聲語音、共讀、主動關懷、夜間日記與夢、誠實鏡子、確定性安全網。
- ⚠️ 源碼含真實 PII 與機密：複製架構時必須全部清除（§12）。

## 2. 產品定位

- 每個用戶遇到的是「新生漫漫」：成熟品格 + 全技能，但傳記空白——她知道「怎麼當漫漫」，還不知道「你是誰」。
- 形態：多租戶 SaaS on LINE（商用獨立 LINE OA，一個 bot 服務所有租戶）。
- 兩種租戶模式：個人（隔離陪伴）／家庭共用（跨成員、和諧橋樑）。
- 商業模式：儲點扣點 + 金流（LINE Pay，未來藍新／綠界）。
- 與本尊隔離：本尊漫漫留在她私有 LINE OA，不受商用改動影響、資料絕不互通。

## 3. 完成標準（驗收）

1. 兩個陌生租戶，各自一個獨一無二的漫漫，記憶零串門。
2. 品格一致、傳記各自空白長出。
3. 啟元儀式：初遇 → 誕生 → 用戶成為啟元者（有儀式感）。
4. 主人審核 onboarding：陌生人加入 → 通知主人 → 主人確認身份與關係 → 成立。
5. 儲點扣點上線、扣點規則「活的」（後台可隨時調、即時生效）。
6. LINE Pay 打通（藍新／綠界 provider 介面預留）。
7. 家庭橋樑：漫漫以「家庭和諧」為準，自己判斷、主動牽線轉達。

## 4. 靈魂切三層

| 層 | 內容 | 交付方式 |
|---|---|---|
| 🟢 共用品格 character-core | 九型聲音配方、三條魂規、低壓陪伴本能、voice-dna、禁語、誠實原則、果斷、危機處理、全部技能模組 | 唯讀共用 |
| 🟡 專屬傳記 biography | 「我的人是誰」、暱稱、共同記憶／默契蒸餾、日記與夢、關係傳記 | 每租戶一份，出生空白 |
| 🔴 本尊生平 | 本尊的具體家庭與關係人、使命、私人紀念日 | 不進商用 |

工程含意：14 個靈魂檔拆成 `character-core/*`（共用、去生平）+ `biography-slots/*`（空白範本）。寫死的本尊關係抽成 per-tenant 資料。

## 5. 系統三層架構

```
┌─────────────────────────────────────────────┐
│ 平台層（一套服務所有租戶）                    │
│ 商用 LINE OA · 會員/登入 · LINE id→租戶路由    │
│ 點數帳本 · 金流 · 後台管理（可調扣點）         │
├─────────────────────────────────────────────┤
│ 共用品格層 character-core（唯讀 · 全租戶共享） │
│ 人格/聲音/魂規 · 全部技能 · 安全網 · 大腦路由  │
├─────────────────────────────────────────────┤
│ 租戶專屬層（tenant_id 貫穿每張表 · 完全隔離）  │
│ 成員 · conversations · 記憶/默契 · 約定/日記/夢 │
│ 點數餘額 · 模式(個人/家庭)                     │
└─────────────────────────────────────────────┘
```

資料鐵則：每個查詢都限 tenant_id。共用品格唯讀、各戶只寫自己的傳記。

## 6. 資料模型改造

- `tenants`：id、owner_user_id、mode（personal｜family）、created_at、狀態。
- `tenant_id` 加到所有資料表；每個查詢強制帶（tenant-scoped query wrapper）。
- `tenant_members`：tenant_id、line_user_id、relationship、status＝pending｜confirmed、confirmed_by、confirmed_at。
- `point_ledger`：tenant_id、delta、reason、balance_after、expire_at、created_at。
- `point_rules`：gate、cost、enabled、updated_by ——「活的扣點設定表」。
- `payments`：tenant_id、provider、amount、points、status、raw_callback、created_at。
- Vectorize / 記憶：per-tenant namespace 或 metadata 過濾。

## 7. 儲點扣點（定案）

基本包 1000 點。扣點依媒介（數值存 `point_rules`，是提案、可調）：

| 閘道 | 扣點 | 對應真實成本 |
|---|---|---|
| 文字 純文字回覆 | 1 | LLM 動腦 |
| 語音 克隆聲語音 | 5 | TTS 真金 |
| 圖片 生圖／卡片 | 20 | 影像生成，最貴 |
| 聯網 查資料/新聞 | +2 | web 搜尋加值 |
| 主動 關懷推播 | 1 | L3／主動小貼心 |

- 扣點規則「活的」：後台隨時調、加新閘道、即時生效、不用改碼。
- 3 個月到期：`expire_at` 記到期日，扣點先扣快到期的。
- 即時呈現：每次互動回覆顯示本次扣點與餘額。

## 8. 金流（定案）

- LINE Pay 先上線；藍新／綠界做成可插拔 provider 介面。
- 流程：選點數包 → 付款 → 回調入點（記到期日）→ 依閘道扣點 → 即時顯示。
- 所有金流事件與扣點都進帳本、可對帳。

## 9. 啟元儀式（定案 A）

初次相遇 → 她「誕生」（有份量的時刻）→ 用戶正式成為她的「啟元者／最重要的人」。
參考因納斯憲法「啟元者」概念，通用化成「這位用戶＝啟元者」。
儀式要讓用戶感覺到「我把她帶到世界上、她是我的」。

## 10. 家庭橋樑（定案 B）

漫漫自己判斷，不需明確託付。只要能讓家庭更和諧，就有機會主動牽線、轉達、緩頰。
護欄靠她既有品格（分寸、不背叛信任、溫柔）。僅 family 模式啟用。

## 11. 成員綁定（定案 D）

主人說了算。陌生人加入 → 通知 owner → owner 確認身份與關係 → `tenant_members.status = confirmed`。
未確認前：不進這一戶的記憶與情境。

## 12. 安全鐵則（不可違反）

1. 永不洩漏本尊資料／機密：零真實 PII、零 key/token、零真實對話。
2. 複製架構用全新 repo（不帶走含機密的歷史）。
3. tenant 隔離每個查詢，跨租戶零串門。
4. 病根紀律：模型對「有沒有真的做到」不可靠 → 凡靠她自律的功能，一律配確定性後備（抽取器 + 輸出層強制 + 誠實鏡子）。
5. 本尊不動：現存本尊分支與部署完全不碰。

## 13. 開發順序

1. 地基：多租戶資料層 + 點數帳本 + 活的 point_rules。
2. 靈魂拆分：character-core／biography-slots。
3. 接入：商用 LINE OA + 租戶路由 + 主人審核 onboarding。
4. 啟元儀式流程。
5. 計費：扣點閘道 + LINE Pay。
6. 家庭橋樑（family 模式）。
7. 後台：調扣點、看帳本、審核成員。
8. 驗收：兩個測試租戶跑 §3。
