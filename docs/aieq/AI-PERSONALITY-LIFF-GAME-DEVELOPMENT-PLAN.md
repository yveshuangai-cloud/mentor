# AI Personality（AI 人格誌）LIFF 成長遊戲開發計畫

日期：2026-09-13  
開發分支：`codex/aieq-mbti`  
狀態：分階段開發計畫；本次僅將討論計畫入庫，不代表各階段已完成或已部署。

## 1. 產品目標與範圍

建立在 LINE LIFF 裡運作的 AI 人格誌成長遊戲：使用者完成八題探索，認識自己的動物特色，再透過每日小挑戰累積 AI 技能與實際成果。

測驗是入口，任務與成長是持續體驗。保留 16 種動物，人格偏好與技能進度分開；不以動物或人格類型判定能力高低，不宣稱官方 MBTI 或心理診斷。

採分階段開發，每階段交付可操作版本，試玩通過後才擴充。第一輪先驗證 Godot 在 LIFF 手機環境中的表現，再決定遊戲畫面的技術選擇。

### 使用者流程

1. 從官方 LINE 選單或朋友分享進入 LIFF。
2. 看見開始頁，選擇語言，開始八題探索。
3. 每題透過動態選項互動，作答進度自動保存。
4. 揭曉動物人格，閱讀特色並確認結果。
5. 選擇成長目標與每天可投入的時間。
6. 進入個人成長地圖，接取第一個任務。
7. 學習小技巧、完成挑戰、提交成果。
8. 收到回饋，解鎖後續節點。
9. 自願開啟每日 LINE 提醒，也可以分享人格卡、邀請朋友。

朋友分享入口先呈現對方允許公開的結果，再引導「我也想玩」。接受邀請先記錄 pending，朋友完成並確認結果後才建立 connection，且需符合雙方同意規則。

## 2. 系統分工

| 層次 | 負責內容 |
| --- | --- |
| LIFF 網頁 | LINE 登入、語言、頁面導航、分享、提醒設定、文字輸入 |
| 遊戲畫面 | 動物動作、動態選項、場景回饋、成長地圖、任務互動 |
| 後端服務 | 驗證身分、保存答案、計分、任務進度、成果回饋、朋友連結 |
| 內容設定 | 八題題庫、16 種動物資料、任務、技能、文案與版本 |
| LINE OA | 官方入口及使用者同意接收的提醒訊息 |

Godot 優先用於遊戲畫面原型，登入與分享保留在 LIFF 網頁層。原型不適合手機時，可改用網頁實作遊戲畫面，保留後端與內容介面。

每日提醒由後端排程配合 LINE OA 發送，不依賴已關閉的 LIFF 頁面繼續執行。本文件只規劃功能，不建立實際排程。

## 3. 第 0 階段：盤點現況、鎖定八題規格

### 工作內容

- 檢查現有 AI 人格誌分支、題庫、計分、資料庫及 LIFF 設定。
- 區分已實作功能、設計稿與待驗證功能。
- 整合 Eve 哥的八題完整題目與選項。
- 明定每題用途：人格偏好、AI 行為或成長目標。
- 確認權重、平手處理、資料不足時的呈現及信心說明。
- 建立題庫與計分版本，保留舊版結果。

### 交付與驗收

交付正式規格、流程圖、八題對照表與現況差距清單。八題未定稿時，可用標記清楚的暫定題目做互動原型，但不定稿分類結果。

舊七題使用者保留原結果；進行中的 session 綁定原版本，新開始的 session 使用新版本，避免混用題目與分數。

## 4. 第 1 階段：LIFF × Godot 技術驗證

以「烏鴉創意工作室」作為第一個小型可玩版本。

### 工作內容

- LIFF 開始頁與測試身分串接。
- 一個場景、一隻烏鴉、一題動態三選一。
- 點選後立即出現動作與轉場回饋。
- 遊戲答案可傳回網頁及後端。
- 完成後回到 LIFF 結果頁，測試分享入口。
- 驗證關閉、切換背景、重新進入及失敗恢復。

### 交付與驗收

在 iPhone 與 Android 的 LINE 實際操作，記錄測試裝置、網路條件、首次載入時間、流暢度、文字可讀性、登入與分享結果。

驗收標準與可接受的效能門檻在原型開始前明定。若 Godot 有明顯載入或相容性問題，遊戲畫面改用網頁實作，沿用同一套後端介面與內容規格。

## 5. 第 2 階段：八題探索與結果確認

### 工作內容

- 八題完整流程、動態進度、選項回饋、角色反應及轉場。
- 支援返回、續答與重複點擊處理。
- 依題庫設定計算題數，不寫死八題。
- 選項顯示位置與答案識別碼分開，調整順序不影響計分。
- 完成計分、結果揭曉與結果確認。
- 保存當次題庫版本、計分版本與結果。

### 交付與驗收

- 能完整完成八題，中斷後可繼續。
- 快速連點不重複計分，舊答案事件不會覆蓋較新的作答。
- 同版本、同一組答案得到一致結果。
- 舊七題紀錄仍能正確讀取。
- 動畫不阻擋閱讀或增加不必要等待；支援減少動態效果。
- 手速、拖拉技巧與動畫表現不參與人格計分。

## 6. 第 3 階段：16 種動物與分享體驗

### 工作內容

- 將現有動物整理成獨立角色素材；完整分享圖片不能直接當成可活動角色。
- 每隻先製作待機、思考、鼓勵、完成四種反應。
- 遊戲內結果頁呈現特色、優勢、盲點與成長建議。
- 接入既有分享卡版型及使用者同意使用的頭像。
- 確認 DigiAsia 小 BABY Logo 的正式尺寸、版式與安全留白。
- 完成圖片生成、下載、分享、朋友入口及 pending 邀請流程。

### 視覺原則

沿用黑底、白字、桃紅動物與稱號、螢光綠副標與細線。動物保持可辨識的瑞士現代主義幾何風格；動物名稱大、四碼小、成長提醒內容清楚。Logo 目前只有單張試排，批次套用前需確認。

### 交付與驗收

- 16 型文字與動物對應正確。
- 分享圖不包含分享或重測等操作按鈕。
- 頭像、圖片載入失敗時提供替代畫面。
- 朋友連結符合雙方同意與結果確認規則。
- 分享取消或失敗不誤記為成功，也不提前建立朋友連結。

## 7. 第 4 階段：第一條個人成長路線

先完成一條路線，再增加內容。起始範例：「把好點子變成可交付成果」。

| 節點 | 挑戰 | 完成證據 |
| --- | --- | --- |
| 換個角度 | 用 AI 提出三種解法 | 提交三種方案 |
| 做出選擇 | 設定判準並選一種 | 說明選擇理由 |
| 驗證想法 | 找出並查證一個風險 | 提交查證依據 |
| 完成作品 | 做出能使用的小成果 | 提交文字、連結或檔案 |
| 根據回饋升級 | 收集一次回饋再修改 | 說明修改內容 |

### 工作內容

- 補問成長目標及可投入時間。
- 建立地圖、節點、任務詳情與進度保存。
- 任務包含簡短知識、操作指引與成果提交。
- 提供「需要幫助」「太難」「稍後再做」。
- 以明確規則判斷任務是否完成；AI 可輔助提供回饋。

### 交付與驗收

使用者可完成整條路線，重新開啟能接續。重複提交不重複領取獎勵，任務回饋能說清楚完成了什麼及下一步是什麼。AI 回饋失敗時保存成果並提供可恢復狀態，不遺失作業。

## 8. 第 5 階段：每日提醒與持續挑戰

### 工作內容

- 自願開啟提醒、設定時間與時區。
- 每則提醒對應一個可直接進入的任務。
- 支援暫停、關閉及調整頻率。
- 發送前檢查任務是否已完成，避免過期提醒。
- 處理失敗重試、重複發送與 LINE 訊息用量。
- 點開提醒可回到正確任務與進度。

### 交付與驗收

同一提醒不重複發送，關閉後停止，已完成任務不再催促。未完成不以斷簽或扣分懲罰。提醒功能在測試環境驗收後再安排正式啟用。

## 9. 第 6 階段：擴充個人化任務系統

### 工作內容

- 建立提問、驗證、創作、整理、自動化、協作等共用技能方向。
- 依目標、熟練度、可用時間與過往成果安排任務。
- 動物影響引導語氣與起始推薦。
- 支援難度調整與替代路線。
- 提供內容編輯方式，讓企劃更新任務與短文。
- 任務與技能設定具備版本，更新不破壞進行中的紀錄。

### 交付與驗收

不同目標得到不同路線，使用者可跨技能學習，不因人格類型被永久限制。共用任務骨架，再調整情境、難度與引導，不預設需要 16 套完全獨立的任務庫。

## 10. 第 7 階段：試營運與正式上線

### 工作內容

- 手機、LINE 版本、弱網路與中斷恢復測試。
- 檢查身分驗證、資料權限、邀請與分享邊界。
- 驗證中英文版面及減少動態效果。
- 觀察載入成功率、測驗完成率、首個任務完成率及分享成功率。
- 檢查 AI 回饋成本、訊息費用與錯誤紀錄。
- 準備備份、版本回復方式及上線檢查表。

### 交付與驗收

先完成測試環境真人驗收，再提供可審核的正式上線版本。正式部署另行確認；將本計畫提交到倉庫不等於授權部署。

## 11. 底層資料與版本原則

| 資料類別 | 保存內容 |
| --- | --- |
| 人格探索 | 題目、答案事件、題庫與計分版本、結果、確認時間 |
| 能力與任務 | 成長目標、任務版本、目前狀態、提交成果、回饋、技能進度 |
| 互動設定 | 語言、提醒偏好、分享同意、邀請與朋友連結 |

- 人格結果不隨任務完成重新計算；技能可持續成長。
- 題目與計分版本綁定 session，修改題數不修改歷史結果。
- 卡片、自然語言等答案進入一致事件格式，使用穩定識別碼與冪等處理。
- 結果確認與任務完成的狀態更新需防止重複執行。
- 測評結果獨立保存，僅在取得使用者同意後作個人化溝通參考。
- 個人化初期依清楚規則安排任務，累積可用回饋後再調整推薦策略。

## 12. 第一輪開工範圍與協作節點

第一輪為第 0 與第 1 階段，交付：

1. 現有程式、八題內容與測試環境盤點。
2. 確定的前後端資料介面與版本策略。
3. 烏鴉單題動態原型。
4. 可在測試 LIFF 開啟的版本。
5. iPhone／Android 試玩紀錄及 Godot 採用建議。

企劃參與題目、任務難度、16 型稱號與成長文案審閱；設計參與動物動作、版面與 Logo 定稿；開發負責資料、互動及串接；使用者或指定驗收人員在每階段試玩並回饋。

日程與工作量在第 0 階段盤點後估算，依實際題目定稿、美術素材與 LINE 測試環境調整，不以未盤點的假設承諾固定工期。
