# AIEQ 精簡互動流程

狀態：2026-08-10 流程減肥版

## 產品裁決

【診斷】情緒＝使用者要的是「我在 AI 時代怎麼生存」的確定感，不是享受答題｜用戶＝不知道自己該怎麼分類、需要情境協助的笨笨｜場景＝LINE 裡被一句話觸發，在兩分鐘內完成並帶走一個可分享結果

【六步】

1. 原動力：測評應交付一個可理解的目前結果，不是讓人反覆刷分類。
2. 必要性：十題、暫停按鈕、同時索取兩項同意都不是完成任務的必要條件。
3. 誠實：重測次數不是價值；反覆測到喜歡的類型只會讓資料更假。
4. 壓力檢查：分享不能暗示排名，接受朋友邀請前要明說完成後會互相看見類型。
5. 簡單檢查：session 歷史、冪等與同意時機由系統處理，不丟給使用者理解。
6. 終閥：保留八題與一次確認是合理的；自動重測不合理，所以刪除。

【裁決】改了再做：profile-first、八題、單一確認、按需同意、禁止自動重測。

【一句話】使用者來做什麼？拿到一個現在有效的答案，然後離開。

## 唯一入口規則

```text
開啟 LIFF／輸入 AIEQ
  ├─ 已有 confirmed profile → 直接顯示目前結果
  ├─ 有 in_progress session → 從目前題目續答
  └─ 兩者都沒有 → 顯示兩分鐘說明與「開始測評」
```

入口不得自行建立 session。只有使用者明確按下「開始測評」，才建立第一個 session。

## 測評主路徑

```text
開始
→ 8 個情境，每題三選一
→ 結果
→ 確認並綁定
→ 我的類型
```

- 預設使用卡片點選；自然語言只是備援，不要求使用者學指令。
- 每題只有三個正式選項與一個「不確定」。
- LINE 使用者需要修改時可輸入「回上一題」。
- 不顯示「暫停」按鈕；直接離開就是暫停，下次自動續答。

## 結果生命週期

```text
none → in_progress → completed_unconfirmed → confirmed
```

- `confirmed` 是唯一對外有效結果；歷史 session 只作稽核，不參與朋友圈。
- 再次開啟 LIFF、點舊卡或輸入 AIEQ，只能回到目前有效結果。
- 第一版不提供重測入口。日後若要做，必須命名為「重新校準」，另定冷卻期與版本規則，不能沿用一般開始流程。

## 同意的出現時機

- 確認結果：只確認結果並綁定 LINE，不同時索取其他授權。
- 朋友可見：使用者第一次按「邀請朋友」時才開啟；受邀者接受邀請即代表完成後加入朋友圈。
- 饅頭個人化：只有饅頭真的準備引用 AIEQ 結果時另行詢問，預設永遠是關閉。

## 防混亂規則

1. 一位使用者最多一個未完成 session。
2. 一位使用者最多一個 canonical confirmed profile。
3. 完成後不因開頁、輸入口令或點舊卡建立新 session。
4. 朋友圈只讀 canonical profile，不讀 session 歷史。
5. 同一 event id 只處理一次。
6. 刪除 AIEQ 資料時一併刪除 session、profile、邀請與 friendship。
